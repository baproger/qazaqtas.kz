# Релиз: финансовый контур — что изменилось и что сделать при выкладке

> Дата подготовки: 16.08.2026. Работа по плану `PLAN-FINANCE.md`, шаги 1–14.
> Тесты: 508 зелёных, `npm run build` чистый, `composer audit` без уязвимостей.

---

## 1. Порядок выкладки (по шагам, не пропуская)

1. **Бэкап базы — обязательно:** `./scripts/backup.sh`. Одна из миграций
   переносит учёт денег по складу и **необратима** (см. §3).
2. Выложить код и собрать фронт: `php composer.phar install --no-dev`,
   `npm ci && npm run build`.
3. `php artisan migrate --force` — миграции этого релиза:
   - связь выплат с сотрудником, таблицы долгов, коды категорий (шаг 1);
   - права ролей: `expense.create` всем, `expense.delete` снят с менеджера (шаг 3);
   - оплата закупа на приходе + **чистка способа оплаты у списаний склада** (шаг 11);
   - наценка позиции склада и цена продажи в списании (шаг 11a);
   - отметка о напоминании по заявке (шаг 13).
4. `php artisan finance:selfcheck` — таблица инвариантов должна закончиться
   строкой «Все инварианты сошлись».
5. Выровнять кассу: Финансы → плитка «Остаток в кассе» → ✎ → фактический
   остаток (см. §3, это единственное ручное действие).
6. Настройки → Этапы: назначить этапу «Товар готов» системный тип
   **«Логистика (возврат из цеха)»** — без него цех не закроет заказ.
7. Настройки → Общие: задать **«Наценка на товар со склада, %»** и проверить
   **«Бонус менеджера от наценки, %»** (по умолчанию 2).

## 2. ⚠️ Плитка кассы изменится — и почему

До этого релиза деньги за товар списывались из кассы **в момент списания
материала в сделку**, а приход на склад кассы не касался вовсе. Это неверно:
поставщику платят при закупе.

Теперь наоборот: **деньги уходят при закупе** (в форме прихода появился выбор
«нал / банк / не списывать»), а списание в сделку — внутреннее движение
запаса. Миграция обнулила способ оплаты у **всех прошлых** списаний.

Следствие: **остаток кассы вырастет** на сумму прошлых списаний — они
перестали вычитаться. Восстановить прошлые закупы задним числом система не
может: она не знает, чем за них платили. Поэтому после миграции остаток
выравнивается **один раз** корректировкой кассы под фактический (шаг 5 в §1).
Дальше цифры идут правильно и сходятся сами.

Что **не** изменилось: маржа сделок, Сводный отчёт, бонусы ЗП — списание как
входило в себестоимость сделки, так и входит.

## 3. Что нового у сотрудников

| Кто | Что появилось |
|---|---|
| Любой сотрудник | **«Мои расходы»** (`/my-expenses`): подать заявку на расход с чеком, видеть статус и что ему выдали (аванс, долг) |
| Бухгалтер, админ | **«Расходы»** (`/expenses-board`): очередь заявок с открытыми чеками, оплата в два клика |
| Бухгалтер, директор, админ | **«Касса»** (`/cash-book`): книга за день с печатным «Отчётом кассира» |
| Бухгалтер, админ | **Долги сотрудников** в ведомости ЗП: выдача из кассы, автогашение из бонуса |
| Менеджер | **Бонус за товар со склада**: процент от наценки по проданному со склада |

Меню: пункт «Финансы» стал группой — Обзор · Расходы · Касса · Мои расходы ·
Зарплата. Каждый пункт виден по своим правам; цеховому открываются только
«Мои расходы» и «Зарплата».

---

## 4. Новые правила, о которых стоит знать команде

- **Расходы удаляет только бухгалтер или админ.** Менеджер, ошибившийся в
  списании материала, просит бухгалтера удалить (остаток вернётся на склад).
- **Подтверждённый расход заморожен** для автора: правит его только бухгалтер.
- **Заявка сотрудника не двигает кассу** — деньги уходят, когда бухгалтер её
  оплатил и выбрал, откуда.
- **Долг гасится только из бонуса.** Нет бонуса в месяце — удержания нет,
  остаток переезжает. Оклад долг не трогает никогда.
- **С этапа «Цех» сделка уходит только кнопкой «В цех»** — ни «Далее», ни
  перетаскиванием. Возвращает её сам цех, закончив заказ.
- **Двойной клик больше не создаёт вторую запись**: ни платёж, ни поступление,
  ни расход, ни сделку из заявки.

## 5. Автоматика (крон)

Плановые команды выполняет `schedule:run` — он уже настроен на проде.

| Команда | Когда | Зачем |
|---|---|---|
| `debts:charge` | 1-го числа, 09:00 | удержать долги за прошлый месяц из бонуса |
| `expenses:notify-stale` | ежедневно, 09:30 | напомнить о заявках, ждущих дольше 3 дней |
| `finance:selfcheck` | вручную | сверка денег: касса, банк, дебиторка, ЗП |

---

## 6. Если цифры не сойдутся

Запустить `php artisan finance:selfcheck` (можно `--company=<id>`). Команда
покажет таблицу «инвариант / ожидание / факт / расхождение» и вернёт ненулевой
код, если что-то разошлось. Это быстрее и надёжнее, чем сравнивать страницы
глазами.
